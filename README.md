# didg - ИИ-ассистент для ИТ/ИБ-дайджестов

Собирает публикации из открытых источников, отбирает их под интересы читателя, склеивает дубли, группирует по темам
и выпускает Markdown-дайджест со ссылками на первоисточники. LLM-агент проверяет и подключает источники и настраивает
их вес по статистике и отметкам читателя.

## Соответствие заданию

| Требование задания | Где выполнено                                                                      |
|---|------------------------------------------------------------------------------------|
| Получать публикации из выбранных источников | `config/sources.yaml`, 31 источник; `collect`                                      |
| Отбирать материалы по интересам пользователя | профили `config/profiles/`, флаги `--interests` и `--stack`                        |
| Группировать по темам, сохранять ссылки | Атака / Уязвимость / Инфо с приоритетом или 12 тегов датасета; у сюжета все ссылки |
| Дайджест в Markdown | `digest` - `output/<профиль>_<дата>.md`                                            |
| Две аудитории: ежедневно и ежемесячно | профили `soc` и `management`                                                       |
| Обратная связь | `feedback`                                                                         |
| Замена модели | `LLM_MODEL` в `.env`                                                               |
| Примеры входных данных и результатов | `examples/`                                                                        |
| Работающий сервис | `streamlit/`                                                                       |

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python cli.py collect
python cli.py digest --profile soc
```

Нужен Python 3.11 или новее, команды запускаются из корня репозитория.
В `.env` указываются ключ Yandex AI Studio `LLM_API_KEY` и модель `LLM_MODEL` с каталогом в адресе; без `NVD_API_KEY`
NVD принимает один запрос в 6 секунд. Необязательно: `LLM_REASONING` передаётся как `reasoning_effort`,
`LLM_BASE_URL` задаёт другого OpenAI-совместимого провайдера.

Без ключа LLM, на снимке из `examples/`:

```bash
python cli.py import examples/articles.jsonl
python cli.py digest --profile soc --date 2026-10-02 --no-llm --no-nvd
```

| Команда | Что делает |
|---|---|
| `collect [--days --only]` | собирает публикации в SQLite |
| `digest [--profile --date --days --interests --stack --no-llm --no-nvd --out]` | формирует дайджест |
| `feedback <профиль> <id> +\|-` | отмечает сюжет как полезный или бесполезный |
| `agent ["задача"] [--profile --yes]` | запускает агента, без задачи — плановое обслуживание источников |
| `eval <файл> [--no-llm]` | сверка с размеченными примерами: попадание в выпуск, группа, приоритет, теги |
| `stats`, `urls`, `export`, `import` | статистика источников, загрузка по ссылкам, выгрузка и загрузка снимка |

## Развёртывание

Веб-интерфейс `streamlit/app.py` локально запускается командой `streamlit run streamlit/app.py`, в облаке -
на Streamlit Community Cloud из репозитория GitHub:

1. Отправить код в репозиторий на GitHub.
2. На share.streamlit.io: Create app, указать репозиторий, ветку и файл `streamlit/app.py`.
3. В Advanced settings выбрать Python 3.12 и заполнить Secrets:

```toml
APP_USER = "demo"
APP_PASSWORD = "<пароль для входа>"
LLM_API_KEY = "<ключ Yandex AI Studio>"
LLM_MODEL = "gpt://<folder_id>/gpt-oss-120b/latest"
NVD_API_KEY = "<необязательно: без него CVSS из NVD не запрашивается>"
```

4. Нажать Deploy. Зависимости ставятся из `requirements.txt`, первый запуск загружает снимок публикаций
   и считает эмбеддинги 2-3 минуты.
5. Чтобы эксперты входили без аккаунта Streamlit, в Settings → Sharing сделать приложение публичным: вход защищён
   логином и паролем из Secrets.

Каждый push в выбранную ветку пересобирает приложение.

## Как работает

```
сбор - CVE/BDU, CISA KEV, CVSS из NVD - эмбеддинги и склейка дублей - гибридный скоринг
     - LLM: оценка топ-40 - LLM: дубли и «Главное» - LLM: карточки атак и уязвимостей - Markdown
```

- **Отбор.** Скоринг учитывает близость к интересам (`multilingual-e5-small`), стек, ключевые слова, CVSS и KEV,
  свежесть, число и вес источников, отметки читателя. Итоговая оценка - 0,5 × скоринг + 0,05 × релевантность
  от LLM по шкале 0-10; сюжет с релевантностью ниже 3 отсеивается.
- **Код и модель.** Ссылки, даты, CVE, отметки KEV, порядок и приоритет по правилу датасета считает код. Модель пишет
  заголовки, краткое содержание, «Почему важно», карточки и «Главное».
- **Проверки.** KEV засчитывается, только если продукт или CVE есть в заголовке или начале статьи. Склейку дублей
  от LLM код принимает при общем CVE, а если у одного из сюжетов CVE нет - при близости по эмбеддингам. Пункты
  «Главное» без опоры на сюжеты выпуска отбрасываются.
- **Без повторов.** Публикации, уже показанные профилю, в следующий выпуск не попадают.
- **Сертификаты.** Сборщик доверяет и стандартным центрам сертификации, и корневому сертификату Минцифры
  `config/russian_trusted_root_ca.pem`: им подписаны сайты Positive Technologies.
- **Устойчивость.** Ошибка источника не останавливает сбор. Ответ модели запрашивается в JSON-режиме провайдера;
  если он не разбирается или в нём нет ожидаемых полей, запрос повторяется обычным текстом и JSON извлекается
  из ответа. Если модель отказалась оценить пачку новостей, пачка делится и переспрашивается, а неоценённые сюжеты
  получают эвристики. Публикации, эмбеддинги, ответы LLM и NVD кэшируются в SQLite. Без ключа LLM работает
  эвристический режим.

**Агент** (`didg/agent.py`) в цикле вызывает инструменты: `overview` - профиль и статистика источников,
`probe_source` - проверка кандидата (свежесть, частота, доля ИБ, релевантность, дубли с базой; у сайта без RSS -
ссылки страницы для шаблона статей), `set_source` - подключение источника или изменение веса. Код ограничивает
решения модели: новый источник подключается только с весом больше 0 и с параметрами, проверенными `probe_source`;
вес подключённого меняется только при 3 отметках или 20 публикациях за 30 дней. Изменения подтверждает пользователь,
строка «Применено» показывает фактически внесённые.

## Сверка с датасетом

`python cli.py eval examples/dataset.jsonl` собирает выпуск каждой аудитории только из примеров датасета
организаторов и сравнивает с их разметкой; `--no-llm` даёт эвристическую базу для сравнения.

| Метрика | С LLM | Без LLM |
|---|---|---|
| Техспециалисты: в выпуске | 9 из 10 | 10 из 10 |
| Техспециалисты: группа / приоритет | 9 из 9 / 7 из 9 | 9 из 10 / 7 из 10 |
| Руководство: теги precision / recall / F1 | 0,85 / 0,77 / 0,81 | 0,90 / 0,41 / 0,56 |
| Руководство: регион «В РФ» / «Вне РФ» | 6 из 6 | 5 из 6 |

Модель `gpt-oss-120b`; с LLM результат от прогона к прогону немного меняется. Расхождения по каждому примеру
команда выводит построчно.

## Ограничения

- Модель отвечает не детерминированно даже при `temperature=0`: повторный прогон немного меняет подборку.
- `aliceai-llm` отказывается оценивать часть новостей на политические темы; они получают эвристики, отказы видны
  в строке «Отбор» как «ошибок LLM».
- Telegram читается через веб-превью: только публичные каналы и последние посты, поэтому сбор нужен регулярно.
- Повторы отсекаются по публикациям, а не по событиям; подборка из нескольких новостей считается одним сюжетом.
- Агент не ищет новые источники в интернете: он сопровождает подключённые и проверяет кандидатов, которых указал
  пользователь. Поиск запланирован в следующих доработках, на эту версию не хватило времени.
